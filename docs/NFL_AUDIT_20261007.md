# NFL Audit — 2026-10-07

Audit of NFL as the Constellation's hash storer / witness. Scope: ledger integrity,
CLI, HTTP API, ingest, CPR delegation, trust. Method: read the actual files + runs
(no label-trust). Baseline commit at audit start: `74447c5`.

## Findings & disposition

### Fixed this pass

**F1 — API cross-origin write exposure (medium-high).** `nfl_api_v1.ps1` sent
`Access-Control-Allow-Origin: *` and never checked the request `Origin`, while
`POST /commit` writes the ledger and `POST /ingest/control` runs PowerShell. The
listener is localhost-only, but any web page the operator visits could drive those
endpoints (CORS cannot prevent the request itself). **Fix:** server-side Origin guard —
a request carrying a non-localhost `Origin` is rejected 403; CORS now reflects only a
local origin instead of `*`. Requests with no `Origin` (curl/PowerShell/local CLI) are
unaffected. Note: `file://` pages send `Origin: null` and are now blocked; if a legit
local `file://` dashboard needs access, allow "null" explicitly.

**F2 — API unbounded reads (medium).** `/ingest/runs`, `/recent`, `/ingest/state`,
`/ingest/failures` loaded the entire file (telemetry had reached ~393k lines) into
memory and reversed it per request. **Fix:** `Read-NdjsonTail` reads only the last
`limit` records (`Get-Content -Tail`), default 500, overridable via `?limit=`.

**F3 — NDJSON validity (medium).** Writers used `Add-Content ($json + "\n")`, which on
Windows emits `\n\r\n` → a blank line between every record; the ledger also began with a
blank line from its init. Strict line-parsers trip on this. **Fix:** `nfl_cli_v1.ps1`
(ledger) and `nfl_ingest_inboxes_v1.ps1` (state + run receipts) now append clean
single-line LF records via `File::AppendAllText`; the API `/commit` append is likewise
clean. **Append-only preserved:** only the writers changed; existing ledger history is
untouched (its old blank lines remain and are harmless — the durable-ledger chain
canonicalizes parsed records and skips blanks).

**F4 — Ingest telemetry runaway (medium).** `nfl_ingest_runs.ndjson` grew unbounded
(one receipt per scheduled run). **Fix:** `Rotate-IfLarge` archives the run-log to
`proofs/receipts/archive/` once it exceeds 5 MB, then it starts fresh. Applied to the
run-log telemetry **only** — never the dedup-state file, whose rotation would re-ingest
everything. Archive dir gitignored.

### Documented, not changed (lower severity / needs a decision)

**F5 — Two CPR entrypoints.** The green path + ingest call
`C:\dev\cpr\scripts\verify_packet_v1.ps1`; `nfl_verify_packet_with_cpr_v1.ps1`,
`nfl_build_packet_with_cpr_v1.ps1`, and the CPR integration self-test call
`C:\dev\cpr\cli\cpr.ps1`. Both exist on CPR, so both work, but the split is latent rot.
Recommend standardizing on one once CPR's canonical entrypoint is confirmed.

**F6 — Dead Tier-0 selftests.** `selftest_vectors_v1.ps1` /
`selftest_verify_packet_v1.ps1` call the quarantined `verify_packet_v1.ps1` stub and
throw `NFL_PACKET_LAW_MOVED_TO_CPR`. Not a false-green (clear throw), but misleading as
"tests". Recommend a header note pointing to the CPR path + the durable-ledger gate, or
retiring them to the frozen bundle only.

**F7 — Mixed commit schema.** CLI commits `{hash,artifact,timestamp}`; API commits
`nfl.ledger.commit.v2` with extra fields. The chain tolerates it (canonicalizes only the
three core fields), but the ledger holds two record shapes. Consider normalizing.

**F8 — No quarantine move.** A packet that fails CPR verify never enters the ledger and
is recorded `ok:false` + marked seen, but is not moved to a quarantine lane (WBS 13).
Acceptable for now; invalid evidence cannot reach the valid ledger.

**F9 — PS-side trust parity.** `verify-seal` pins a single key; the Python export
verifier additionally supports `--trust-bundle` + `--root-pub`. Bringing those to the
live Windows gate is the open follow-on from the durable-ledger milestone.

**F10 — Full-green receipt writer** still uses the `Add-Content` double-newline pattern
(gitignored telemetry only). Low priority; same fix as F3 if desired.

## Proof

- Durable-ledger gate `NFL_DURABLE_LEDGER_GREEN_OK` + Python export self-test 9/9
  (unchanged by these fixes; chain is line-format agnostic).
- CLI full-green `NFL_CLI_FULL_GREEN_OK` — also AST-parse-gates the edited CLI, API, and
  ingest scripts, so a syntax slip fails loudly.
- Fresh `nfl_cli_v1.ps1 commit` produces a clean ledger line with no trailing blank line.
- API origin smoke: a request with `Origin: http://evil.example` → `FORBIDDEN` 403; with
  no Origin → `COMMIT_OK` / `OK`.
